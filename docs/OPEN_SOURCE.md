## 源码许可方向

用户要求不允许基于受许可约束的代码推出闭源衍生发行版。新写代码使用 AGPL-3.0-only：允许商业使用和收费，受约束的衍生版本分发须提供相应源码；修改版支持网络交互时，还涉及向交互用户提供对应源码的要求。

该许可不阻止他人独立实现相似功能，也不等于所有内部使用或私下修改都必须向公众公开。第三方材料保留原许可，不能把它们直接重标为 AGPL。

已为本目录的新写代码添加 LICENSE、SPDX 源码头和 NOTICE；不覆盖上级工作区、历史 Weasel 代码、第三方材料或图标。来源与哈希见 [sources/README.md](../sources/README.md)。正式发布前仍需按实际打包组合复核。

### Apple 发行需单独审查

未来若通过 App Store 分发 iOS 版本，需要结合届时商店条款、实际代码 / 词库许可、签名和分发方式专门核对。GPL / AGPL 与商店附加限制存在需要处理的兼容性问题，不能默认沿用 Windows 方案，也不能仅凭历史案例断言所有具体组合都绝对不可发行。

自有代码的附加许可或分发例外只能由拥有相应权利的人决定，不能替第三方词库 / 库擅自授权。涉及更改开源保护目标的方案必须交由用户决定，不能在工程中悄悄放宽。

- 授权来源不清或不能满足条件的组件先排除；确有必要再取得明确授权。

## 谁负责什么

| 事项 | 开发方负责 | 用户参与 |
| --- | --- | --- |
| 方案、实现、测试 | 完成技术工作、记录证据与修复 | 产品取舍与日常体验反馈 |
| 数据 / 依赖 | 来源调查、许可清单、替代方案、署名与打包 | 仅在权利或产品目标存在冲突时拍板 |
| 个人开源身份 | 准备署名、仓库说明与发布资料 | 确认有权公开相关成果；提供希望公开的署名方式 |
| 图标 | 原件保存、平台适配、GPT 生成来源与发行记录 | 已确认 GPT 生成并用于本项目；仅在实际权利 / 品牌取舍出现问题时再参与 |
| GitHub | 仓库结构、流水线、发布流程 | 在本机完成必要登录授权，确认发布归属 |
| 签名 | 技术集成、签名验证与安装测试 | 身份核验及确需承担的费用；可行时调查合规的开源签名支持 |
| Apple / 手机 | 实现和自动测试、平台限制调查 | 必要设备 / 开发者账号与真机操作；发行方式的最终取舍 |

本机凭据只在本机处理，不要求发送密码、API Key 或签名私钥到聊天。未来执行发布时先完成可审查的产物与清单，再处理确需用户参与的账号、身份和最终决策步骤。
