# 实施规格与当前边界

更新：2026-10-23。当前已安装未签名本机验收版。最新数字快捷键、Shift、浅色和TI的代表性实际输入已获用户确认；不代表所有宿主、长时或正式发行验收完成。证据见[数字快捷键报告](testing/2026-10-23-number-choices.md)。

## 项目边界

`transinput-next/` 独立存放新写源码、文档和用户提供的图标。未链接 librime、Weasel、Mozc 等输入引擎，未复制这些项目的实现。Windows 原型直接实现微软 TSF 接口。当前 Cargo 依赖仅有工作区内的两个 crate，未引入外部 crate。

当前已连接并验证：

1. Rust 核心 → C ABI → C++ 调用测试：使用已核查的 65,125 条第三方基础词表，支持拼音查询、组合编辑、候选提交和独立会话。自编小词表仅作为单元测试 fixture。
2. C++ TSF → 异步命名管道 → 独立 Windows SDK 宿主 / Rust 核心 → 原始输入上下文：真实词库、异步编辑、上屏与生命周期。
3. TSF → 异步翻译通道 → 独立翻译后台 → Rust 翻译 C ABI → 系统 JSON / 异步 WinHTTP：保留中文候选、仅选中行显示英文，支持等待与显式 F5 重试；结果按组合、候选和配置版本校验。翻译模式下1/空格当前中文、2英文、3中英、Enter原始拼音；方向键/鼠标切换中文，Ctrl+Enter和点击英文保留。未启用翻译/敏感输入按普通中文数字选词规则处理。
4. 当前用户托盘设置原型 → DPAPI / 原子保存与显式测试连接。离屏布局、后端配置和网络分别测试；真实点击流程尚未验收。
5. 经用户授权的九句固定虚构文本已通过真实 DeepSeek，旧版凭据仅在测试内存中读取，配置未变；详见 [真实接口报告](testing/2026-10-21-deepseek-live.md)。
6. 原始 TSF 中文上屏成功 → 敏感类型复核 → 异步学习队列 → Rust 有界偏好 → 当前用户 DPAPI / 原子保存。学习与 DLL 重载的双架构完整结果见 [学习报告](testing/2026-10-21-learning.md)。
7. 自有原生 RichEdit → 过程内 TSF → 自研服务，已完成 SDK 自检及用户本机代表性输入反馈；候选布局通过异步只读会话跟随活动光标。基础混输的用户实际按键反馈见 [混输报告](testing/2026-10-22-mixed-input.md)，最新57项完整回归见 [混写报告](testing/2026-10-22-mixed-spelling.md)，不等于系统安装或其他软件兼容。

早期固定词条已从 TSF 运行路径移除。协议、线程与 DLL 卸载策略见 [ADR-0002](decisions/0002-windows-broker.md)。不得把管道等待、词库或网络调用塞进按键回调。

当前设备为公司电脑，用户无管理员权限，并确认只能使用这台设备。开发、编译、转换与隔离测试在当前账户下执行；桌面工具登录错误单独跟踪，不阻止这些工作。系统输入法安装 / 注册能否在该账户完成尚未验证，不能将可运行的 CLI 当作免管理员系统安装方案。

## 已实现的事件约定

| 事件 | Rust 核心 | Windows TSF 原型 |
| --- | --- | --- |
| 字母 | 小写化、在光标处插入、更新候选 | 同步更新逻辑态，后台整份快照查询，异步返回真实词库候选 |
| 左右 / 退格 / Delete | 中间编辑，光标有界 | 相同，原生选择范围跟随光标 |
| 上下 / 数字 | 选择当前页候选；无效序号不提交 | 相同；最多 90 个候选，每页 9 个 |
| PgUp / PgDn | 有界切换候选页 | PgUp / PgDn 或未按 Shift 的 `-` / `=`；数字 / 鼠标选择当前页，编辑后回首页 |
| 空格 | 提交所选中文，清空一次 | 不合并提交事件；按接受顺序写回原上下文 |
| Enter / Esc | 原拼音提交 / 清空 | 相同，取消时结束原组合 |
| 失焦 / 上下文移除 | 调用方显式 reset | 清理未提交更新，已接受提交仍绑定原上下文 |
| 只读 | 平台负责过滤 | 读取 TSF 状态，透传按键 |
| Ctrl / Alt / Win 组合键 | 平台负责过滤 | 透传；配对处理已消费的 keyup |
| 翻译关闭 / 失败 | 独立翻译状态机；中文不依赖它 | 组合开始时固定模式；等待 / 失败可选中文，英文或双语必须为当前有效结果 |
| 组合态标点 | 平台转换 | 常用逗号、句号、顿号、分号及 Shift 标点与当前中文一起有序提交；未返回候选时保留原拼音与标点作故障回退 |

Rust 与 TSF 组合中支持拼音分隔符 `'`，显式分隔词使用词表原有音节信息。基础简拼按多音节词的每音节首字母匹配，如 `nh`、`srf`；全拼补全用有界范围索引代替按字母顺序扫描前512键。已支持词条内全拼/首字母混合，并接受混写中的zh/ch/sh声母，例如 `srufa`、`zhguo`；显式分隔须落在音节边界。基础/个人词共用新音节树，每个索引查询最多8192边访问和512终端访问，不枚举指数级拼写组合。完整词条与已有简拼保留首屏，其余合法混写词优先于碎字。任意混写片段参与整句仍未实现，见 [混写报告](testing/2026-10-22-mixed-spelling.md)。

基础混输使用 Caps Lock：未提交中文在第一个英文字符到来时先提交当前中文，再按原字符追加；Caps / Shift 在按键边界捕获。空闲英文透传，尚有上屏命令时可打印 ASCII 使用原上下文有序队列，避免数字或符号越过中文。中文后的0、数字键盘和非候选符号也按边界提交，普通1～9仍选词。英文字符不查询中文候选、不进入翻译或学习；不自动识别小写英文、网址和邮箱。实现、限制和本轮证据见 [混输报告](testing/2026-10-22-mixed-input.md)。

中文标点仅在组合中生效，空闲标点由应用处理；完整标点模式和无障碍仍需实现及验收。字面转换仅接管单字符可打印 ASCII，国际布局 / 死键 / AltGr 仍待专项验收；使用 `ToUnicodeEx` 的无状态修改标志，要求 Windows 10 1607 或更新版本。敏感输入标记已过滤翻译，但实际密码框兼容仍需逐应用验证。

候选窗已接鼠标选择，不激活窗口。按下和松开必须指向同一行；内容 / 选中项 / 组合修订变化、隐藏或失焦后取消本次按下。只有提示状态变化的重绘不取消点击。提交前再核对当前 TSF 文档、只读状态与候选版本，经既有编辑队列写回原上下文。纯状态及测试专用 COM 入口用于自建宿主验证，正式 DLL 不提供该测试接口；实际桌面命中区域与点击仍需验收。

## 队列和错误

- 组合最多 128 个 ASCII 字符；候选池最多 90 项，页快照最多 9 项。达到组合长度上限时原型不再追加，仍可删除、提交或取消；清晰的边界提示尚待正式 UI 实现。
- TSF 编辑队列最多 64 项，仅可合并相邻的未提交组合更新，不能合并或覆盖中文提交。
- 本地候选为无编辑副作用的查询，瞬时超时 / 断管最多有界重查一次，以覆盖后台预留管道但词表尚在冷加载的情况。该规则不适用于已消费输入、学习或 DeepSeek 付费请求。
- 普通中文模式候选未返回时，空格 / 1 / 标点保留有序提交占位；2–9 保留一次条件选择，界面提示“正在选词”。有效序号提交对应中文，无效序号或查询错误保留原拼音组合；后续命令按顺序继续。失焦后保留已经接受的选择 / 提交，丢弃最后未提交草稿，不改写新输入框。
- 待选命令与编辑队列共同受 64 槽位预算约束，预留 2 槽；不在按键线程等待候选。捕获的标点与翻译模式不在稍后的回调中重读。待选期间消费的 Return / Esc / 导航 / 删除仍只属于组合操作；若前面的选择已结束组合，不异步重放成应用的发送、移动或删除。组合结束后的新按键正常透传。无组合的已接受空格、数字、分隔符和标点保留为文字。
- 队列满返回 `ERROR_BUSY`，该键未被接受；排空后可重试。此边界已自动测试，但真实应用中的拥塞提示与透传体验尚未验收，不能作为日常版交付。
- `RequestEditSession` 失败回滚此次入队和逻辑编辑，防止未接受文字在未来按键中重放。宿主随后异步拒绝写入时记录失败并丢弃该批待处理操作，不能将故障写入称为成功提交。
- 异步拒写 / 宿主终止组合时，编辑和待选命令共同失效，清理条件选择标记；旧回调不能让新输入一直进入旧待选队列。停用时，待选之后的连续选择也保存原拼音回退，未确认的尾部草稿取消。
- 编辑会话保存原始 `ITfContext` 与操作内容，不能用“当前窗口”替代返回目标。宿主主动终止组合时失效后续旧操作，优先防止向新光标位置误写；此竞态需扩展真实应用验收。
- COM 对象、组合 sink、异步会话计入模块存活；释放完毕才允许 DLL 卸载。测试使用实际 `FreeLibrary` 验证。

## C ABI v1

公共接口在 `bindings/transinput_core.h`。句柄是单调分配的 `uint64_t`，不是跨语言裸对象指针；最多同时 256 个引擎。字符串为显式长度的 UTF-8，单个槽位 512 字节；快照由调用方拥有，不保留 Rust 内存引用。

写入前验证空指针与容量；结构尺寸和 ABI 版本由接口查询。MSVC x86 的局部结构体可能仅 4 字节对齐，因此 Rust 使用 `write_unaligned`，不对外部缓冲区构造 Rust 引用。无效参数不能消费按键，旧句柄不能复用，读取快照不能重放提交。

调用方必须保证缓冲区有效、可写，不能传入任意无效地址并期望 Rust 捕获访问异常。销毁全部句柄、结束并发调用后执行 `ti_shutdown`，返回成功才卸载；`-4` 表示仍有使用者。

基础词表在核心库首次创建引擎时解析，此后缓存同一份 Arc，避免关闭一个输入上下文后，下个上下文重新解析整份词表。显式 shutdown 在无句柄 / 并发使用者时释放缓存；这取代了小词表阶段的 Weak 缓存策略。Windows 后台接入时应在后台初始化核心，不能让第一次词表加载发生在宿主按键回调内。

## 本地选词学习

最多 512 条拼音 / 中文偏好，仅对当前基础与个人词的最多 90 个候选排序，后续页选择可提升到首页；C ABI 在 `bindings/transinput_learning.h`，最多 16 个模型句柄、导出 512 KiB，导入失败不替换旧内存模型。新增 `ti_learning_record_with_words` 使用指定个人词快照与基础词共同验证候选，旧接口仍仅验证基础词。偏好模块不新增词条；排序按该拼音最近明确选中的记录优先，次数仍计入原格式，但不采用纯频次排序。

TSF 在整个中文编辑操作成功后才记录，原编辑 cookie / 输入类型复核允许才发送；预览、取消、失败、只读、敏感输入、原拼音 Enter 与英文 / 双语不记录。学习队列最多 64 条，优先处理输入查询与提交；学习失败不能回滚或重放文字。

独立候选后台在查询线程就绪后加载偏好；加载期间基础中文正常，新学习可跳过以避免导入覆盖。主线程按停顿 / 周期执行原子保存，查询不持文件锁。文件损坏保留原件并退为内存排序；保存失败不阻断中文。托盘设置“中文输入”页已连接开关、清空与保存状态：独立 DPAPI 偏好文件 `learning.bin.settings` 仅保存版本和开关；关闭停止新记录、保留原排序，清空先持久保存空密文再切换内存。Status / Enable / Clear IPC 不返回词条内容；有界管理队列及近期身份去重，客户端不重放结果不明的清空。详见 [学习管理报告](testing/2026-10-22-learning-controls.md)。

## 手工个人词库

Rust `UserWords` 和 `bindings/transinput_words.h` 已接入后台 / 设置 / TSF：最多1024项，同一连写拼音32项，词条32个字符 / 128字节，拼音128字节。完整拼音优先，并参与现有beam9整句切分。音节用空格分隔可生成多音节首字母简拼；至少两个连写字母可补全。没有音节分隔时不猜简拼。编辑时重建简拼与有序全拼索引；查询只访问匹配前缀的范围，最坏受1024条上限约束，补充候选最多90项，不扫描基础词表。

真实简拼且不是基础全拼前缀时优先于偶然碎字组合；普通前缀补充放在基础首屏9项之后（不足9项则接在已有候选后），不改变常用短前缀原首屏。完整个人词合并后应用选词记忆，明确选择的基础词或个人词可升到首位。删除后旧偏好只能重排当前存在的候选，不能重新插入该词；基础词仍能组成的同字文本不屏蔽。个人词按分隔音节建立混写树，支持词条内全简拼混合；单字母不做普通前缀补全，混写片段整句仍待实现。管理和偏好存储见 [个人词检索与排序](testing/2026-10-22-personal-retrieval.md)，新增匹配见 [混写报告](testing/2026-10-22-mixed-spelling.md)。

模型通过不可变Arc快照共享。后台主线程准备独立模型、保存DPAPI的 `user-words.bin`，成功后短锁发布；管理队列8项、近期32身份去重，客户端只提交一次，之后查询结果。列表每页12项，从同一快照读取，按词条 / 拼音身份删除；中文候选仍每页9项。新接口为WordInfo24字节、WordRow1040字节，不改变原5712字节快照。损坏文件保留并拒绝修改；清空学习不影响手工词库。详见 [个人词报告](testing/2026-10-22-personal-words.md)。

## 翻译调度约定

已实现纯调度器、翻译 C ABI、独立 Windows 网络宿主、TSF 翻译交互、敏感标记过滤和托盘设置原型。详细实现与来源见 [ADR-0003](decisions/0003-deepseek-transport.md) 和 [ADR-0004](decisions/0004-windows-settings-prototype.md)：

- 候选稳定 160 ms 后才允许调度，中文至少一个汉字且最多 200 个 Unicode 标量。
- 最多 1 个在途任务和 1 个可替换的最新待发文本；取消 / 关闭后必须等待传输确认结束才能释放在途名额。
- 用请求 ID、会话、修订号和配置 epoch 校验结果。开关切换即使账号不变也使旧结果失效。
- 内存缓存最多 512 项，配置变化清空；超长 / 空响应拒收，不自动无限重试。
- 提示词、自然美式英语风格、模型和账号必须纳入配置身份；网络层只能提交当前固定提示词和本次原文，不建立会话历史。
- `bindings/transinput_translation.h` 的调用方拥有 4,968 字节快照，读取状态不消耗任务；仅 actor 调用 poll / finish。最多 16 个调度器句柄，跨语言写入允许未对齐缓冲区。
- 版本化提示词为 `prompts/translation-system-v1.txt`；每次只有 system + 当前中文 user 两条消息。采用核对当日官方文档后的 `deepseek-flash`，明确关闭思考。
- WinHTTP 请求总预算 3 秒，JSON 32 KiB、译文 4 KiB；取消确认后释放在途名额。禁用重定向与自动认证，TLS 校验不放宽。
- 新版配置存取采用当前用户 DPAPI、当前用户文件 DACL 与原子保存；没有创建真实新版配置，没有迁移或修改旧版真实配置。真实接口测试只在内存使用旧版已保存凭据。
- 翻译后台有独立管道、4 个 IPC 线程与 1 个 actor；客户端进程身份与本地会话编号共同隔离上下文，避免多个应用编号相同导致串用。

仍待完成：候选 / 设置的完整桌面交互、真实宿主隐私兼容、完整输入质量、长时资源与安装验收。不能继承旧版接口或安装测试。
