## P0：实施规格与来源清单

执行环境补充：用户确认只能使用当前公司电脑，无管理员权限。仅在当前账户权限内工作，不修改公司安全策略，不再假设存在其他测试机；实际窗口自动化阻塞不阻止词库 / 核心 / 翻译等可隔离工作继续推进。P1 真实应用验收仍是系统安装与正式交付前的必要条件。

- 确定 Windows 首版的系统版本、硬件、x86 / x64 宿主清单与输入体验样例。
- 记录编辑态、候选态、翻译态和配置态的事件表，尤其是关闭翻译、失焦和后台重启时的行为。
- 评估基础词库和扩展词库，逐文件追溯来源，固定可再分发版本 / commit / 哈希。没有明确授权的资料不进入构建。
- 核对 Rust、Windows SDK、通用库与 UI 框架的版本及传递依赖，建立来源和许可证清单。
- 规划 GitHub 目录、品牌记录和未来源码许可；此阶段不默认创建公开仓库。

## P1：系统接入与可移植性原型

- 独立 GUID / 标识注册新 TSF，不能覆盖旧版 COM 标识；目前先在自建进程内测试，安装评估按当前账户可行路径推进，与旧版并存作为恢复路径。
- C++20 接入固定测试候选，验证组合、修改、上屏、取消、失焦和 DLL 卸载。
- Rust 核心最小接口验证编码、所有权、取消、错误返回及后台退出后的恢复。
- 验证普通桌面、Electron / Chromium、Office、受限宿主和 UILess 场景；决定候选窗进程位置。
- 固定测试机、词库规模和性能测量方法，形成延迟、冷启动、帧耗时与资源预算。
- 验证同一最小核心可被 Apple / Android 工程链接；需要相应设备 / SDK 后执行，不在 Windows 上声称完成 Apple 真机验证。

## P2：中文输入核心

- 从有限且授权清楚的基础词库开始，自研转换工具与校验；先定义内部数据格式，再导入数据。
- 依次实现拼音切分、整句候选、排序、选词学习和数据恢复。
- 用固定语料记录预期候选、实际排名、修正次数和学习效果；词库越大不等于首选候选越准确。
- 快速输入与编辑场景先通过，再增加基础简拼和中英文混输细节。
- 数字待选、分页、学习管理、Caps基础混输、手工个人词及其简拼/补全/最近选择排序、基础与个人词的词条内全简拼混写已实现。下一步完善正式输入质量、任意混写片段的整句与混输扩展；用独立用例覆盖，不能只扩大“全部通过”的措辞。频次记录保留，排序仍按最近选择优先，新增匹配边界见 [混写报告](testing/2026-10-22-mixed-spelling.md)。

## P3：翻译与设置

- 核对 DeepSeek 官方当前接口与模型可用性，Key 在本机保存，不要求用户发到聊天或提交源码。
- 固定提示词版本；实现稳定等待、1 在途 + 1 最新待发、缓存、取消和结果版本校验。
- 实现普通中文模式、等待中、成功、失败四类可见行为；无任何本地翻译模型与离线回退。
- 设置只包含必要项目；测试连接使用固定虚构文本。真实用户文本采集不属于自动验收默认范围。
- 网络、证书、鉴权、限流、空响应、异常响应和闲置连接逐项验证。

## P4：安装与可用性

- 将原始图标生成各平台所需资源，并执行小尺寸与深浅背景视觉检查；原件保留。
- 测试干净安装、升级、重复安装、重启、用户数据保留和卸载。
- 自动测试、真实宿主输入、持续输入、故障注入及长时资源趋势分别出具报告。
- 在当前电脑的独立测试进程内做有界故障测试，再开展真实宿主验收；不假设其他设备可用，不用全机卡死作为压力测试目标。

## P5：GitHub 开源与发行

- 保持旧版工程和新项目来源边界；不将当前整个工作目录直接推送。
- 准备 README、LICENSE / NOTICE、构建指南、贡献规范、隐私说明、安全报告方式、更新记录和依赖清单。
- 锁定源代码、词库、依赖和构建版本；流水线用固定虚构文本，不内置发布者 DeepSeek Key。
- 发布源码 tag、安装包、校验和及已知问题，构建签名与发布权限分开管理。
- 账号认证、证书身份验证、付费与最终发布归属由用户处理；可自动完成的资料与技术流程由开发方准备。

## P6：平台扩展

- macOS：原生候选、Apple Silicon / 所需 Intel 架构、全屏与多桌面、签名公证、原生应用体验。
- Android：多输入类型、触控、横竖屏、不同 DPI、系统回收恢复、目标设备性能和发布签名。
- iOS：键盘扩展冷启动与内存、网络完全访问、宿主设置与安全共享、系统禁用第三方键盘的边界、真机和发行许可核对。
- 各平台复用核心测试数据与词库；界面不强制像素相同，保持产品语义与视觉语言一致。

## 执行记录原则

每一阶段完成后记录环境、源码版本、词库版本、实际命令 / 操作、结果、证据和未通过项。没有执行的任务保持“未执行”，失败记录保留，不以旧版结果替代新实现结果。
