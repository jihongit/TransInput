# 基础简拼、补全与组合态标点回归

日期：2026-10-21。环境沿用 TSF 翻译报告，无管理员操作、系统注册或旧版替换。

## 修复与范围

1. 之前 `nh / zg / bj / srf / rgzn` 无候选。现在从已审查第三方词表的音节边界生成首字母索引，支持整词基础简拼。`nh` 首选“你好”、`srf` 首选“输入法”、`rgzn` 首选“人工智能”；`zg` 的“中国”和 `bj` 的“北京”均在第 2 位。
2. 之前补全只扫描按字母顺序的前 512 键，会漏掉后面的高频词。改为排序前缀范围和词频范围索引，每次至多访问 512 个最高权重条目，字典按键位置不再决定是否被扫描；多音去重及候选最多 9 项保持有界。
3. 显式 `xi'an` 可匹配词表的“西安”，不依赖字表恰好含可单独切分的字；重复、首尾分隔符不产生候选。全拼补全如 `sh` 仍首选“是”；无全拼前缀的 `nhm` 优先整词简拼“你好吗”，避免稀有语气词拼接抢首选。
4. 组合中按逗号、句号、顿号、分号及对应 Shift 标点，提交当前中文与标点。候选尚未返回时将两者放在同一个有序操作中；后台失败 / 退出保留原拼音与标点。空闲时标点透传，未实现完整标点模式或中英文混输。

不是扩充或重写词表；原始及转换数据哈希保持不变。简拼不是任意全拼 / 简拼混合匹配，现代词汇与整句排序仍待改进。

## 实际验证

命令：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify-windows.ps1 -Architecture all`。

最终证据 `artifacts/p1/20261021-210023-396/`：25 项全部退出 0，含源文件哈希。两架构各 30 个 Rust 单元、4 个词表集成测试；`fixtures/chinese-quality.tsv` 的 40 条固定全拼 / 简拼 / 补全 / 分隔样例全部达到列明的候选排名。

原生测试覆盖简拼穿过真实 Rust / 管道 / TSF，候选已就绪和未就绪的标点、未知输入回退、关闭回退、翻译等待期间标点与迟到英文过滤。每架构 1024 次快速提交中交替使用空格和逗号，文字与标点顺序一致；原上下文提交、队列上限、焦点、只读及原有网络故障检查继续通过。x86 TSF 仍连接共享 x64 中文后台。

## 失败记录与测试修正

`artifacts/p1/20261021-205559-320/` 首次在 TSF 简拼步骤失败，后续诊断表明首次后台启动超出了测试固定 100 ms 等待。改为有 2 秒截止时间的结果条件等待，实际冷启动观察 250～344 ms，包含测试消息泵采样间隔，未放宽生产管道时限。
