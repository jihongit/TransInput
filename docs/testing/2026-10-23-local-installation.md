## 已发现并处理的问题

1. 双架构共享profile/类别：第二架构允许识别同版本另一架构的已注册路径；卸载先删除单架构COM，最后一架构才清除共享TSF信息，拒绝覆盖不同版本/路径。
2. Windows PowerShell对无BOM中文字符串的解析及其原生命令stderr行为不同：安装器的本地化名称改为明确Unicode码点，边界测试采用独立输出日志，保留真实退出码。
3. 首次实际安装（11:53）x64注册成功，x86在目录保护检查处返回5。`FOLDERID_ProgramFilesX64` 不支持32位进程，回退会得到Program Files (x86)。现从操作系统64位注册表视图读取受保护ProgramFilesDir，保持相同目录边界。[微软KNOWNFOLDERID说明](https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid)
4. 官方UnregisterProfile仍会留下空TIP容器。补充最后一架构的官方Unregister服务调用；首次失败的暂存内容已逐文件核对哈希、确认两架构COM和用户启用均不存在后清理。首次失败日志、残留核对及清理记录均保留在 `artifacts/installation/20261023-115337-591/`，微软拼音保留。
5. 卸载先核对用户输入法状态，再删除自身维护脚本；按DLL、程序、资料、维护脚本顺序清理，文件占用时保留卸载记录及“已反注册”状态，允许重试，不强制关闭其他应用。
