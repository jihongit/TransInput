# 词条内全拼与简拼混合输入

日期：2026-10-22。Windows 10 Enterprise x64 19045、Rust1.99.1、MSVC14.44.35207 / SDK26100。固定虚构语料与自有 SDK 输入宿主；不读取个人输入/Key，不请求 DeepSeek，不注册系统输入法。

## 当前行为

基础词与有音节分隔的个人词支持词条内混合拼写：每个音节可用完整拼音或首字母，混写时也可用 zh/ch/sh 双字母声母。例如 `shuruf`、`shurfa`、`srufa`、`srfa` 可匹配“输入法”，`zhguo` 可匹配“中国”，`ni'h` 可匹配“你好”。显式单引号必须落在音节边界；不能跳过中间音节，不做任意截字母的模糊匹配。

个人词如“星河研究所” / `xing he yan jiu suo` 可用 `xinghyjs`、`xhyanjs`、`xing'h'yan'j's`。没有分隔的个人长拼音仍可完整输入和前缀补全，但不猜测内部音节。当前是已知词条内匹配，不是任意混写片段参与连续整句切分；既有完整拼音整句能力继续保留。

直接完整词条（含显式分隔）和已有整词简拼保留原候选首屏；其他情况下，合法混写词优先于偶然碎字组合。修正了 `diann` 中“电脑”被“点嗯”等碎字挤到第10位的情况。普通个人词前缀补全仍保留基础首屏；最近明确选词的记忆在所有候选合并后排序，完整/简拼/混写分别按当前拼音记录，关闭/清空行为未改。总池90、每页9、成功提交才学习的边界保持。

## 工作量与实现

新写 `spelling.rs` 建立音节树，不枚举每个词的所有全拼/简拼组合，不增加外部依赖。基础索引在词表加载时建立，个人索引在明确编辑/恢复时重建；共享词条引用，不按键重建基础词表。

查询沿首字母对应的边访问，优先访问高词频分支；状态按节点/输入位置/匹配标记去重。每个索引查询最多8192次边访问、512次终端条目访问；基本索引与个人索引分别有界。超过预算停止补充，保留已找到结果与基础通路，不保证极端同首字母语料找全所有低权重匹配。音节完整与缩写都须出现才进入新增混写结果，纯全拼/纯简拼仍由原通路处理。

二进制文件格式、C ABI布局、IPC版本与密文存储未变。已存在候选验证 API 同时使用新增检索，因此只有当前候选能被学习；不允许任意模型文字或外部文本注入词库。

## 失败与修正

1. 旧用例要求 `srfa` 为空；新功能应当支持 s+r+fa，更新为验证“输入法”，没有删除非法输入检查。
2. 新质量用例暴露 `zhguo` 不识别双字母声母及 `diann` 排在碎字之后，分别补齐声母和候选合并优先级；没有降低22条首屏要求。
3. 首个 TSF 探针 `artifacts/mixed-spelling/20261022-224042-224/` 失败为“fixed SDK key was not consumed”。原辅助 Type 只接受字母，却把单引号按字母算术转码；修正为 VK_OEM_7 并显式拒绝不支持的固定样例字符。没有改变系统键盘状态或注入按键。
4. 首轮完整检查 `artifacts/p1/20261022-224332-665/` 在新增完整拼音保护样例失败。样例中合法同音词“泥岸”权重20高于“年”10，原全拼排序本就会将其排前。调整固定样例“年”为100，仍保留混写竞争项1000000，分别验证完整/分隔匹配不被混写覆盖。修正后46单元+6词表集成定向通过；最终以下述全套为准。
