## 实现调整

- `bundled_dictionary()` 读取固定生成数据，CLI 与 C ABI 改为使用它；平台无关引擎算法继续自主实现。
- 较大的基础词表解析一次后缓存同一份 Arc，避免每次关闭 / 打开输入上下文重复加载。无活跃句柄或调用后，`ti_shutdown` 显式释放缓存，再允许卸载。此实现替代首轮小词表阶段的 Weak 缓存方式。
- 新增 3 项真实词表集成测试：基础数据与 10 个首候选样例、长 / 非法输入边界、编辑提交一次及独立会话。
- 验证脚本加入上游哈希和转换一致性检查；Git 属性保留原件与转换结果字节，避免 Windows 检出时自动换行破坏哈希。

## 算法计时

环境同首轮报告。release CLI `--benchmark`：10 组固定拼音循环 100 轮，1,000 次组合全部提交，共 8,000 个字母事件。只测本地 `Engine::apply(Letter)`，不包含 UI、系统键盘投递、IPC、网络或进程启动。

| 首次实测指标 | x64 | x86 |
| --- | --- | --- |
| 进入 main 后解析词表 | 32.424 ms | 38.149 ms |
| 字母事件 P50 | 0.0314 ms | 0.0373 ms |
| P95 | 0.1282 ms | 0.1835 ms |
| P99 | 0.1855 ms | 0.2635 ms |
| 最大值 | 27.6307 ms | 0.6961 ms |

x64 出现一次明显长尾，原因未定位；保留原结果，不能只报均值。复测的 x64 / x86 P95 分别为 0.1258 / 0.1861 ms，最大值分别为 0.3425 / 0.5780 ms。两轮原始 JSON 保存在 `artifacts/p2/benchmark-{x64,x86}.json` 及 `benchmark-repeat-{x64,x86}.json`。当前数据不能证明真实候选窗端到端延迟达标，也不能据此保证无长时卡顿。
