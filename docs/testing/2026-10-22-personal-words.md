这是个人词管理首次接入阶段的记录。后续简拼、补全和选词排序已扩展，当前行为及新检查点见 [个人词检索报告](2026-10-22-personal-retrieval.md)；本报告保留当时的实现边界与测试证据。

日期：2026-10-22。沿用 Windows 10 Enterprise x64 19045、MSVC 14.44.35207 / Windows SDK 26100、Rust 1.99.1。只记录自身 SDK / RichEdit 与原生设置控件、固定虚构文本和隔离临时文件；未执行系统安装、其他应用打字或真实模型请求。

## 当前行为

设置新增“个人词库”页，填写词条和拼音即可添加，选择已列词条后可删除；列表分页读取，每页12项。中文词条最多32个 Unicode 字符 / 128个 UTF-8字节，不能包含空白或控制字符；拼音最多128个 ASCII 字节，仅字母、空格、单引号，大小写 / 音节分隔会规范化。`ü` 使用 `v`，不接受数字声调。这里只校验格式，不宣称能自动校对多音字读音。

最多1024个条目，同一连写拼音最多32项；超限明确失败，不逐出旧词。相同词条和规范化拼音重复添加不增加数量。修改可删除旧条目再添加；目前没有批量导入 / 导出或自动采集个人新词。

例如添加“星河研究所” / `xing he yan jiu suo` 后，输入完整 `xingheyanjiusuo` 可选该词；`nihaoxingheyanjiusuo` 与 `xingheyanjiusuonihao` 可和基础词组成“你好星河研究所” / “星河研究所你好”。自定义词的完整拼音优先，短前缀不会把大量新词插在首选；个人词的简拼、部分全拼补全尚未接入。

单独输入同拼音新词时，目前采用稳定的文字顺序，普通选词偏好仍仅按基础候选校验，不对新增词自动增频。删除取消的是个人条目及其优先级；若基础词库本身能组合出相同文字，删除不会屏蔽基础候选。已经开始的组合不强制重写，新查询读取最新词库。

## 存储、线程和边界

- 词库独立保存到 `%LOCALAPPDATA%\TransInputNext\user-words.bin`，使用当前用户 DPAPI、当前用户文件权限和原子替换，保留原有加密存储实现；不新增第三方依赖。首次空读取不创建文件。
- Rust 模型使用 `TIW1` 严格有界格式，明文最大320 KiB，包含版本、修订号、数量及显式长度的 UTF-8条目。错误版本、截断、尾部多余数据、重复条目、非法字符 / UTF-8和超限被拒绝，不能部分导入。
- 修改先在独立准备模型中完成与校验，序列化、加密和写文件均在后台主线程。磁盘成功后才发布不可变快照；候选查询只短暂克隆 Arc，不持模型锁读磁盘或构建索引。
- 独立词库参与现有 beam9整句切分，候选池仍为90、每页9。完整拼音条目优先；固定排序先验不是实际使用频次。共享基础词表65125项不修改，也不会为每个按键复制或重建整份基础词库。
- 设置使用异步任务。8项管理队列、32项近期身份记录防止重复执行；删除按原词条和拼音身份，不按容易过期的列表行号。未确认结果只查状态，进程重启后的旧操作显示未知，不自动重发添加 / 删除。
- 列表从同一个不可变快照读取，避免修改期间出现新旧页混合。接口是新增 C ABI和IPC8/9/10，原5712字节组合快照及已有协议保持原样；完整构建包中的后台和核心需匹配。
- “中文输入”的学习开关和清空记录与手工词库分开；清空偏好不删除手工词条。损坏词库保留原文件并拒绝修改，基础中文仍可查询；当前不提供一键重建损坏词库。

词库文件、列表和个人词条不会批量上传。用户启用 DeepSeek 后，当前高亮中文候选仍可能包含手工词条，并按已确认的翻译规则发送；页面有明确说明。隐私输入类型仍过滤翻译，其他实际宿主的标记兼容性需分别验收。
