# 基础中英文混输与上屏顺序

日期：2026-10-22。环境沿用 Windows 10 Enterprise x64 19045、MSVC 14.44.35207 / SDK 26100、Rust 1.99.1。本报告只记录自有 SDK / RichEdit 宿主及明确的本机人工反馈，不代表其他 Windows 应用或系统安装验收。

## 行为

- Caps Lock 关闭时继续输入拼音；普通 1～9 仍为候选选择，翻译模式下 2 / 3 仍按当前译文状态处理。不自动猜测小写单词是英文还是拼音。
- Caps Lock 开启后输入英文。若还有未提交中文，先提交当前所选中文，再追加英文字符；大小写依键盘的 Caps / Shift 状态保留。关闭 Caps Lock 后可继续输入中文。
- 中文的异步上屏尚未完成时，后续 ASCII 字符加入原上下文的有序队列。处理完成后，空闲英文、数字和符号继续交给应用；不为了英文建立中文组合、查询词库、翻译或学习。
- `nihao` + 空格 + `2026` 可依次提交“你好2026”；在中文组合中直接输入 `0` 也会先提交中文再追加 0。数字 1～9 的选词含义保持不变，所以要输入完整年份，应先用空格完成中文选择或切到英文。
- 中文组合内原有逗号、句号等仍为中文标点；英文状态使用键盘产生的原符号。`Shift+2` 的 `@`、`Shift+'` 的双引号及 `Shift+=` 的加号不再误作候选序号、拼音分隔符或翻页键。未加 Shift 的拼音分隔符与组合态翻页仍保留。

示例：先输入 `nihao`，打开 Caps Lock 后输入 `GPT`，再关闭 Caps Lock 输入 `ceshi` + 空格，结果为“你好GPT测试”。这属于显式模式的基础混输；自动识别小写英文、网址和邮箱等仍未实现。

## 实现边界

`LogicalKey` 保存按键回调捕获的字面字符和英文状态。延迟选词、排队或后续切换 Caps / Shift 时，执行已接受命令不会重新读取修饰键，也不向宿主补发按键。复用64槽总预算及2槽预留；满载明确返回忙，不能把未接受的字符标为已消费。原上下文提交、取消、停用和错误处理沿用已有队列。

正式路径按当前键盘布局调用 `GetKeyboardState` / `ToUnicodeEx`，使用 flag bit 2 避免改变死键状态；当前接管单字符可打印 ASCII。负返回值、多字符和非 ASCII 字面转换不由本功能猜测；国际布局、死键和 AltGr 组合仍需专门验收。Ctrl / Alt / Win 快捷键继续透传，未新增模拟键盘、全局键盘监听或模式快捷键。该转换要求 Windows 10 1607 或更新版本，不据此承诺更早版本兼容。[微软 ToUnicodeEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-tounicodeex)、[键盘状态](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getkeyboardstate)。

测试 DLL 的固定 US ASCII 键码转换仅用于 SDK fixture，不读取或改变用户实时键盘状态 / 布局；它不等同于正式路径的真实键盘捕获。正式 DLL 不暴露测试入口。没有新增第三方依赖、API 请求、真实用户配置或词库迁移。
