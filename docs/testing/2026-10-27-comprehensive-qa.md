## 新增缺陷 QA-001：配置晚到导致首段不翻译

优先级：**P1，阻止翻译功能完整验收**。状态：已稳定复现，未修复。

复现是项目测试进程内的实际 TSF 服务和实际候选后台，翻译使用隔离夹具，不联网、不用真实 Key。仅给翻译夹具的初始 `ReadState(session=0)` 增加 750ms 延迟，模拟后台首次启动或配置读取尚未返回，而不是把配置显式设为关闭。

步骤：

1. 新建隔离服务，夹具配置已启用翻译，立即输入固定拼音 `nihao`。
2. 等中文候选就绪，继续泵送消息约 2.5 秒，超过配置延迟。
3. 记录英文就绪状态与实际收到的翻译观察次数。
4. Esc 取消后重新输入同一个 `nihao`，再次记录。

| 架构 | 首段英文就绪 | 首段请求数 | 重新输入后英文就绪 | 累计请求数 |
|---|---|---|---|---|
| x64 | 否 | 0 | 是 | 1 |
| x86 | 否 | 0 | 是 | 1 |

这不是接口慢或 DeepSeek 报错：第一段根本没有发送翻译观察。探针退出码 1 正确表示测试失败，没有为了全绿修改判据。

源码对应链：`D:\ai_open_demo\truns_input\transinput-next\platforms\windows\tsf\async_translation.h` 初始 enabled 尚未知时按 false 提供；`D:\ai_open_demo\truns_input\transinput-next\platforms\windows\tsf\module.cpp:1514` 读取该值，同文件第 1374 行在新组合开始时固定 translation_mode；后台配置后来发布 session=0 状态，第 993 行开始的活动会话校验不让它重新启用本次组合。因此已启用配置无法让第一段追赶翻译。该受控复现支持这一根因链；不能断言历史所有“无英文”都只有这个原因。

本机探针与证据：总证据目录内 `cold_probe.cpp`、`translation_fixture_delayed.cpp`、`build-cold-probe.cmd`、`cold-probe-x64.txt`、`cold-probe-x86.txt`。探针与运行时源码分离，不进入产品安装。修复后的验收应包含：配置晚到时当前候选能追赶翻译，同时不发送已取消、失焦、敏感或旧修订内容，保持 UI 线程非阻塞。
