# 原生编辑器、本机人工测试与候选定位

日期：2026-10-22，Asia/Shanghai。当前公司电脑、当前账户，无管理员权限。独立测试窗口不等于系统输入法安装，旧版 0.17.4.6 未替换。

## 原生编辑器

新增 `TransInputTestHost.exe`，使用系统 msftedit.dll / RichEdit 的真实文本存储与 TSF 编辑会话。过程内 profile 和类工厂不持久注册、不改默认输入法。测试窗口显式路由自己的消息到自研服务，避免经全局按键管理器误测其他已安装输入法。自动自检调用 SDK sink，使用离屏、不激活的自身工具窗口，没有 OS 键盘注入。

抽出公共 `test_support.h`，不再包含另一个测试 cpp 或重命名其入口。独立候选后台、临时路径和无网络翻译 fixture 与现有集成测试共用；不读取真实 Key 或学习文件，测试模式关闭学习。交互窗口内文字关闭后不保存。复制运行的步骤与限制见 [操作说明](INPUT_PAD.md)。

自检覆盖中文提交、Esc、光标中间插字、退格 / Delete、原拼音 Enter、第二页数字选择、替换原生选区、32 次快速连续提交、只读状态与恢复、失焦取消与恢复，并核对没有翻译调用。对原生只读状态通知使用有界等待，不假定消息发送后马上更新。固定回调改用测试 DLL 内的显式修饰键，局部调用原有 OnTestKeyDown / OnKeyDown / 配对 keyup，不设置 OS 键盘状态，返回后立即清除测试覆盖值；正式 DLL 不暴露此入口，人工窗口不使用它。另测 Ctrl / Alt / Win / 空闲 Caps 透传、非法掩码拒绝和 Shift 标点。失败只记录固定测试阶段、固定键码与状态，不记录人工输入。

## 本机人工反馈

最初正常启动在窗口显示之前读取 TSF 文档，程序报 `native RichEdit has no TSF document` 并提前退出，用户反馈没有看到窗口。已改为先显示自己的交互窗口，再有界等待原生上下文；隐藏 SDK 自检继续保留。

修复后的隔离副本为 `artifacts/manual-input/20261022-150531-470/`。进程检查见到自身窗口且响应正常，用户在本聊天按提供的少量步骤反馈“看到了，输入正常”。该反馈仅验证此窗口的代表性输入，不能扩展为记事本、浏览器、Office、全局输入法安装或整个矩阵通过。

后续布局版 `.../20261022-152829-079-x64/` 的人工检查发现：移动整个窗口候选不跟随，调整大小能够跟随。该项记为失败，不能以 43 项自动检查覆盖它。原因是只订阅 TSF 文本布局，根窗口移动没有触发相应通知。继续补充当前宿主进程内的 `EVENT_OBJECT_LOCATIONCHANGE`，只匹配当前编辑窗口及其根窗口，重用异步只读定位；不监听其他进程、不改宿主窗口过程、不使用轮询或键盘 hook。回调表只保留弱引用，取出后释放互斥量再调用 COM；同线程解绑，计入模块存活。

移动专项 `artifacts/move-probe/20261022-153559-486/` 已通过：自己窗口的位置事件能刷新、同一进程无关窗口被忽略、不增加文字写入、正式上下文和 DLL 释放正常。新版 `.../20261022-153728-265-x64/` 的人工反馈为“移动和调整大小都正常跟随”。该项已复测通过，不能据此扩展为其他软件和多屏场景通过。

## 候选窗位置

此前候选定位取整个组合范围，只在文本编辑会话中刷新。现改为查询当前活动光标的折叠范围；上下文的 `ITfTextLayoutSink` 通知触发一个有界的异步只读会话。每个上下文同时最多一个定位读取；通知不重放文本、中文查询或提交。源对象持有弱引用 sink，状态释放时解绑；挂起读会话计入模块存活。

布局缺失、裁剪、零高度、隐藏 / 最小化时撤下旧位置的窗口，保留逻辑候选，后续有效布局可以恢复。不能把无效坐标当作屏幕原点。定位和文本写入分离，定位失败不让中文编辑成为失败提交。

自建 TSF 文本存储扩展检查：组合中间的光标位置为 3 时定位范围也是 [3,3]；原生读锁挂起期间 32 次布局通知不读取未授权文本，释放后请求合并；读取锁为只读，不增加文字写入；提交后的布局通知不继续查询旧组合。正式 / 测试 DLL 生命周期继续检查。

依据：[微软布局通知](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itftextlayoutsink-onlayoutchange)、[编辑会话权限](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfcontext-requesteditsession)、[不可见范围返回值](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfcontextview-gettextext)、[进程过滤及回调线程](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)、[同线程解绑](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-unhookwinevent)。

## 持续输入与资源

`--soak-seconds=10..28800` 只在自己的离屏编辑框反复提交固定“你好”，穿插取消、清空自身固定文字与空闲。每五秒采样本进程及其自有候选后台、无网络 fixture 的 private bytes、句柄、GDI / USER 对象和累计 CPU；不查询其他应用内容。`scripts/soak-windows.ps1` 设置外部超时，只终止自身测试进程树。

暖态上限为每个进程相对起点增加 32 MiB、32 个句柄或 8 个 GDI / USER 对象；这是检测失控增长的测试边界，不是已冻结的产品内存目标。文字正确性与资源边界分别检查，不能只看进程还活着。

布局修复前的实际 60 秒记录：x64 `artifacts/soak/20261022-150928-908/`，720 次提交；x86 `artifacts/soak/20261022-151106-304/`，680 次提交，全部正确且未触发资源上限。x64 编辑器 private bytes 起 / 止为 10,096,640 / 9,949,184，句柄 538 / 533，GDI 22 / 22；x86 为 9,285,632 / 8,798,208，553 / 548，22 / 22。这些结果不自动继承为后续布局改动的资源结果。

继续修正测试宿主隔离：保持 `TF_TMAE_NOACTIVATETIP`，移除会自动准入无关已安装服务的线程管理器重启；自身 TIP 始终显式激活。背景测试取不到当前文档时，按官方接口读出并恢复自身编辑框的文档关联，不修改其他窗口；仍有两秒上限并记录失败诊断。另一次启动矩阵报实时修饰键“inconclusive”，因此固定 SDK 修饰键与真实物理捕获分开验证。该阶段后仍有下述失败，最终结果见冻结检查点；不声称用几次重试排除所有偶发问题。

`.../20261022-160018-300/` 再次在 x64-native-resources 启动失败，诊断为 `own_focus=0 thread_focus=0 edit_style=0x00010000`：TSF 已启用，但隐藏原生控件并未取得焦点。把“隐藏窗口可以稳定获得系统焦点”作为测试前提不成立。最终 SDK 夹具改为屏幕范围外的 `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE` 窗口，仅发送控件初始化通知并设置自己的 TSF 文档，不调用 Win32 SetFocus 或改变用户前台；测试 DLL 显式抑制候选弹出。断言窗体完全位于虚拟桌面之外、没有成为前台。人工窗口保持正常显示与真实按键。

离屏试验 `artifacts/native-startup/20261022-160821-174/` 的前台保护断言拦截过一次激活，随后移除自检中的实际 SetFocus。`.../20261022-161408-595/` 在“通道不可用”新增用例失败：TSF 会回退到默认文档，SetFocus(nullptr) 不能保证 GetFocus 返回空，因此该测试实际上接受了一次新字母。改为向实际路由函数明确传入缺失上下文，等待异步队列后检查不写文字，再验证正常恢复；通道缺失时阻止按键落到其他输入法，不把他方输入作为自研通过。
