## 本轮发现并修正

1. **32 位快照对齐**：C ABI 先前拒绝仅 4 字节对齐的合法 MSVC 栈缓冲区。实际错误 `apply returned -1; handle=2 size=5712 align=8 pointer-mod8=4`。Rust 改为 `write_unaligned`，增加故意偏移 1 字节的缓冲区回归测试；实际 x86 / x64 DLL 调用均通过。
2. **失败入队重放**：请求编辑会话失败时，入队操作可能残留。调度前预分配，失败恢复原队列；按键逻辑、光标与所选候选同时回滚。满队列恢复测试确认被拒绝的字母不会在后续提交中重放。
3. **异步组合清理**：自身结束 composition 的回调不能误清随后排队的新输入；失焦清理未提交更新时保留已接受的提交顺序。取消 / 回调 / 焦点路径已纳入原生上下文测试。
4. **翻译旧结果归属**：关闭再开启相同配置也递增 epoch，旧任务不能污染新组合；正在取消的请求保留唯一在途名额，直到确认结束。这部分只验证状态机，没有验证网络层。
5. **卸载与缓存**：字典共享缓存使用 Weak，全部句柄结束后显式 shutdown 释放状态；COM 异步对象计入模块存活。测试执行实际 DLL 卸载。
6. **只读与按键配对**：只读上下文不吞字；达到组合长度边界的按键仍正确配对 keyup。原型候选窗代码的间距 / 字体采用相同 DPI 缩放，但视觉效果尚未验收。

## 测试设施问题与处理

- 初始原生宿主直接调用 TIP Activate 时，`AdviseKeyEventSink` 返回 `0x80070057`。修正宿主为进程内 profile 选择及 ThreadMgr 正式激活，通过真实 SDK 路径测试，没有通过删除订阅或伪造成功绕过。
- 只读 TextStore 最初只改布尔值，漏发 `OnStatusChange`。补发状态通知后验证开启 / 解除只读均正确。
- 曾观测测试期间 Ctrl 按下导致固定字母不被消费，诊断 `ctrl=-127`。测试只读取修饰键状态并最多等待 2 秒；持续干扰明确报告 inconclusive，不修改键盘状态。
- Windows PowerShell 对短进程可能返回空 ExitCode：启动后保留 process handle，空退出码视为失败。
- 首次完整检查的末尾收集哈希时误引用了根目录不存在的 `fixtures/`：已修正为由 `crates/` 覆盖实际词表目录，完整脚本随后退出 0。
- 早期重复执行曾覆盖同名日志，关键失败已在本文保留。脚本现改为每次独立证据目录，避免后续覆盖失败记录。
