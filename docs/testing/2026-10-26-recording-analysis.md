# 录屏分析：候选空帧与英文提交中间态

2026-10-26，用户提供本机MP4并要求仔细分析。原视频和提取帧仅保存在本机私有分析目录，不纳入源码导出或Git提交。此次只做分析和记录，没有修改/重装运行时，也没有将视频或文本发给DeepSeek。

## 方法与观测范围

Windows Media Foundation本机解码，928×484，30fps，时长8.267秒，共248帧。逐帧检查候选首行高亮、编辑首行的字形范围和像素变化，并查看转折点原始帧。记录位于 `artifacts/instant-commit/resume-20261026/video-095901/`：frames.csv、frame-metrics.json、timeline.json、关键帧及对照图。

每帧约33.3ms；视频没有键盘事件叠加，不能把候选关闭时刻当作精确按键时间，不能排除两帧之间更快的内部逐字符处理。原始帧中可见的文字、窗口和时间，与对窗口来源/内部机制的推断分开记录。

## 与代码对应的判断

1. **候选空帧已有直接对应。** Publish在候选原文与当前输入不匹配时清空显示列表，Refresh只把空帧绘制延后40ms。录屏中的空列表持续67–167ms，证明这种短时合并不足以消除等待较长时的闪烁；只是继续调大延迟不能替代完整状态设计。
2. **提交存在明显的可见中间态。** Choose入队成功后立即清空逻辑输入并隐藏候选；入队成功不等于宿主已经完成文字替换。录屏中约0.467秒的间隔支持优先核对这段时序，但具体耗时不能仅凭视频全部归于RequestEditSession或某一内部调用。
3. **小空白浮窗的来源未确认。** 其尺寸与固定460×198候选窗不同，可能涉及系统IME兼容窗口或宿主提示窗口；没有窗口类/所有者证据前不能断言。应通过本项目内受控诊断确认，不绕过失败的桌面工具自动操作外部窗口。
4. **状态提示有误导。** 列表空白期间仍显示“正在翻译”，但当前中文候选尚未到齐，应该区分本地候选更新与模型请求状态。
5. **无英文截图仍是独立未解决项。** 这段录屏中的本次输入翻译成功，不能代替此前带句末“呢”的无英文截图验收。后台已开启而组合可能在配置未返回时锁定关闭的冷启动分支仍需单独受控复现。
