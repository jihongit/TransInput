## 问题与处理

普通中文候选未返回时，原实现只有空格 / 1 的提交占位。2–9 被消费，但没有执行选择。直接把所有数字改成提交还会带来另一种错误：无效序号把原拼音错误上屏。

现在 2–9 创建条件选择，暂时保留原组合。有效候选返回后提交对应中文，无效序号或查询失败则保留拼音。随后已经接受的组合命令有序执行，不能用候选预览的“只保留最新”策略合并输入。旧预览也不能排在条件提交之后重新写回旧拼音。

待选命令与编辑队列共用 64 槽位预算，接收待选命令时预留其中 2 槽；没有新增同步等待。标点和翻译模式在接受物理按键时捕获。回调只处理组合命令，不向系统或其他应用注入按键。若 Return / Esc / 导航 / 删除在待选期间被作为组合命令接受，而前面的选择已结束组合，它们不会被异步变成应用的发送、移动或删除；组合结束后的新按键仍正常透传。

失焦后，已接受的选择和提交继续写回原 `ITfContext`，最后未提交的草稿取消。停用时对已接受、尚未解析的提交保留原拼音作回退，关闭不等待后台。宿主拒绝写入属于失败，不能把该批文字记为成功或进行学习。

## 验证方式

新增独立场景 `tsf-integration.exe <测试 DLL 绝对路径> --digits`。自建 SDK 宿主使用实际 TSF 上下文和真实第三方词库；测试 DLL 能暂存自身收到的候选消息及注入错误状态。正式 DLL 不暴露这些测试接口，没有环境变量或注册表覆盖入口。

覆盖：

- 候选消息被暂存时分别按 1–9，释放后与后台对应索引一致。
- 连续新拼音、空格、标点、光标中间插入、退格、取消和无效 9。
- 失焦、切换文档、保留原上下文、停用以及有界拥塞和恢复。
- 超时 / 异常候选结果后保留中文输入；恢复后新输入不重放旧请求。
- 每架构 1024 次快速选择第二候选；共 3072 次按键回调单独计时。这个时间不包含系统物理按键分发、候选绘制或网络，不能当作可见端到端延迟。
- 待选中文成功上屏后才学习；常规数字用例不产生学习文件，正向学习用例仅使用专属临时文件。
