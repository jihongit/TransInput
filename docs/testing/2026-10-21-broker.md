# 独立后台与 TSF 连接报告

日期：2026-10-21。已把 Windows TSF 与真实 Rust 词库连通，不再走固定词条。实际桌面应用 / 可见候选验收仍被测试运行器 1385 阻塞，尚未安装新版。

## 本轮实现

- 独立 `TransInputBroker.exe` 承载 Rust 核心，C++ 只处理 Windows SDK 传输与生命周期；完整决策见 [ADR-0002](../decisions/0002-windows-broker.md)。
- 新增整份组合查询 C ABI，一次重算完整拼音，不跨进程重放每一个前缀。非法输入 / 光标不修改旧状态，不产生提交副作用。
- 定长头、小端逐字段编码、有界负载的本机协议；logon SID ACL、远程拒绝、服务端进程路径核对与测试 PID 校验。分段读写、取消后确认完成，未用默认公开 DACL 或无限 Flush。
- TSF 使用异步通道，候选预览可替换最新快照，已接受提交单独 FIFO。候选未返回时空格提交加入原上下文占位，后续写入不得越过该占位。
- 结果校验会话、文本修订、请求 ID 及原文；跨焦点结果仍绑定原上下文。工作线程不持有 COM 对象，不在 UI 线程 join；线程池在回调返回后释放真实 DLL 引用。
- 核心不可用 / 停用时保留未解析提交的原拼音；这属于核心故障降级，后续需验证提示体验，不等同于“翻译失败时改为拼音”。

## 限制与后续

- SDK 文本宿主返回无可见布局，结果不能冒充记事本 / Chromium / Office 的真实打字与候选窗测试。
- 队列满仍明确拒绝未接受工作；核心失败的拼音保留提示、实际宿主切换、外部光标移动、无障碍和 UILess 必须继续验证。
- 预览只更新最新快照；按键本身仍逐一编辑并保存。后台最多 8 个处理线程，单通道最多 32 个待处理提交 / 64 个总任务，模块最多 8 个通道，压力规模之外尚无结论。
- 不把上述有限回归称为已完成 8 小时资源测试或全机卡死问题根因保证。
- DeepSeek 网络、翻译侧后台、设置、用户学习及安装仍在后续实施范围。候选计算后台不承担网络 I/O。
